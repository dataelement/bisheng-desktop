# 企业版三方插件市场与工作台能力 PRD

版本：2026-10-14

范围：bisheng 企业版 Desktop
状态：待评审

## 1. 背景

企业版目前在安装包内写死策略：社区插件安装关闭，社区插件从活动 Profile 隔离，工作台总开关在通用设置里隐藏。结果是任意第三方插件和工作台都不能新增安装，也不能当作用户可开关的能力使用。

本次改为由登录租户的服务端策略分别控制两件事：

- 是否允许从企业插件市场以外安装第三方插件。
- 是否允许从网络工作台市场安装第三方工作台。本机自行开发的工作台不在这个开关里。

桌面端负责执行。服务端不能代替客户端拦住本地文件、URL 或其他本机安装入口。

## 2. 目标

1. 管理员在 BiSheng「客户端 → 企业插件 → 安装设置」分别控制两个开关，按登录租户保存。
2. 打开三方插件市场时，设置里出现插件市场入口，用户可以安装网络插件。
3. 关闭三方插件市场时，用户只能从「来自企业」安装插件。
4. 设置里、在「来自企业」之后提供工作台入口。用户自己选择是否开启工作台；开启后，左侧出现工作台入口。
5. 打开三方工作台市场时，工作台列表使用网络工作台市场数据。关闭时，不展示公开市场；本机开发安装仍可用。企业上传目录见 [企业工作台目录 PRD](enterprise-workbench-prd.zh.md)。
6. 两个开关独立。只打开其中一个时，另一个的网络安装仍然被拒绝。

## 3. 非目标

- 不改变企业插件的目录、离线包和「来自企业」安装流程。分发使用在线席位和发布快照。
- 不把企业插件市场里的管理员导入、员工安装算进「第三方插件」开关。
- 不要求在开关变为关闭时卸载、停用或删除已经安装的插件、工作台和用户数据。
- 不禁止用户卸载已安装内容。
- 企业上传工作台的目录、详情和原包核对见 [企业工作台目录 PRD](enterprise-workbench-prd.zh.md)。该能力不包含安装，也不改变本文对公开市场安装的拒绝。
- 不改变官方 DSH 安装包的社区市场策略。本文只约束 bisheng 企业版 Desktop。

## 4. 名词

| 名词 | 含义 |
| --- | --- |
| 企业插件 | 当前企业租户经现有市场发布和下发的插件，入口是「来自企业」 |
| 网络插件 / 第三方插件 | 企业插件市场以外的来源，包括社区插件市场、URL、本地压缩包和其他本机安装入口 |
| 网络工作台 / 第三方工作台 | 从公开工作台市场、npm、GitHub Release 或远程地址新安装的工作台 |
| 本地工作台 | 用户在本机开发并安装到本机的工作台，以及本机已经安装的工作台。不含本次从网络市场新拉取的包 |
| 工作台功能 | 用户在本机打开后，左侧出现「工作台」，可在会话与工作台之间切换。这是本机偏好，不是服务端开关 |

## 5. 服务端契约

管理员页文案与关闭后的含义：

| 字段 | 管理页文案 | `false` 时客户端行为 |
| --- | --- | --- |
| `allow_third_party_plugins` | 允许安装第三方插件 | 拒绝从企业插件市场以外的来源新增安装第三方插件 |
| `allow_third_party_workbenches` | 允许安装第三方工作台 | 拒绝从网络工作台市场及其他远程来源新增安装。本机自行开发的工作台仍可本地安装和使用 |

两个字段独立，按登录租户保存。服务端未配置时两个字段都为 `false`。已上线企业不主动打开开关时，升级后仍不能安装网络插件和网络工作台。`false` 只约束对应的新增网络安装，不要求卸载、停用或删除已安装内容，也不禁止卸载。

客户端读取：

```http
GET {BiSheng公开地址}/api/v1/dsh/market/capabilities
Authorization: Bearer <DSH access token>
```

约定：

- 使用现有登录流程取得的 DSH access token。不使用 refresh token、浏览器 Cookie、管理员凭证或个人访问令牌。
- 公开地址沿用 DSH 客户端接口契约里的同一个 BiSheng 地址。客户端不直连 Gateway 或数据库。
- 请求不传 `tenant_id`、`user_id` 或 `X-DSH-Market-Tenant` 来选择策略。服务端从已认证身份确定租户，并按当前会话和席位状态验证凭证。
- 响应头 `Cache-Control: no-store`。响应用 BiSheng 统一信封，先确认 `status_code === 200`，再读 `data`。
- 现有 capabilities 字段继续按原合同使用。本次新增消费的是下面两个布尔字段。

成功示例（管理员打开了插件开关、关闭了工作台开关）：

```json
{
  "status_code": 200,
  "status_message": "SUCCESS",
  "data": {
    "enabled": true,
    "contract_version": 2,
    "tenant_id": "2",
    "max_upload_bytes": 536870912,
    "sync_seconds": 60,
    "allow_third_party_plugins": true,
    "allow_third_party_workbenches": false
  }
}
```

示例里 `enabled`、`contract_version`、`sync_seconds` 描述「来自企业」通道，与本次两个开关无关，不要用它们推断第三方开关。`allow_third_party_plugins` 与 `allow_third_party_workbenches` 由管理员分别配置，二者没有默认联动。

客户端解析：

| 情况 | `allow_third_party_plugins` | `allow_third_party_workbenches` |
| --- | --- | --- |
| 值为布尔 | 使用该值 | 使用该值 |
| `status_code === 200` 且字段缺失 | `false` | `false` |
| 字段存在但不是布尔 | `false` | `false` |
| 未登录、请求失败、信封不合法、`status_code !== 200`、`data` 缺失 | `false` | `false` |

缺字段、类型错误和整包失败都按关闭，对齐服务端「未配置即为关闭」。不能因为这两个字段缺失或类型不对而让整个 capabilities 解析失败。未知的其他字段忽略。

读取时机：

- 企业登录成功、恢复已有会话、切换租户、退出登录。
- 打开设置中的插件页或工作台页。
- 每一次新增安装或从网络来源更新之前再读一次。界面上一次成功结果只用于展示入口，不能单独作为安装许可。
- 切换租户后丢弃上一租户的结果。在途安装若身份已变，按失败结束，不落到新租户。

2. **工作台**。企业登录有效时出现，紧跟在实际可见的前一个页签后面。三方插件市场关闭时，它直接排在「来自企业」右侧。

左侧栏：

- 用户未开启工作台时，不显示「工作台」。

## 8. 插件市场

### 8.1 打开

`allow_third_party_plugins === true` 时：

- 显示「插件市场」页签。
- 允许从社区插件市场浏览、安装和更新网络插件。
- 允许该能力覆盖到的其他新增安装入口，但每一次安装仍要在执行前确认当前租户的开关仍为打开。
- 以前因企业版策略被隔离、尚未删除的社区插件，不自动重新启用。用户需要自行安装或启用。内置宿主插件的保护名单保持不变。

### 8.2 关闭

`allow_third_party_plugins === false` 时：

- 不显示「插件市场」页签。
- 安装包自带的官方插件可以启用和停用。判定与插件页「官方」分组相同，使用 Harness 的 `OPTIONAL_BUNDLES`，不按包名前缀猜测。终端、Agent 循环、子智能体、网页搜索是官方配置页，不受这个开关影响。
- 「添加插件」只接受本机绝对路径目录和本机压缩包。包名、Git 地址、远程压缩包和自定义 npm 源在查询注册表之前拒绝。
- 已经从网络安装的第三方插件留在「已安装」里，可以继续使用、停用、卸载，也可以再次启用。再次启用只改本机开关，不从网络拉取。`dshmarket` 是插件市场入口本身，这个开关关闭时不能启用，避免市场页重新出现。不自动隔离、停用或删除，不删除用户数据。
- 用户在本机开发、通过本机目录或本机压缩包安装的插件可以安装、启用、停用和卸载。
- 「来自企业」的安装、更新、启用、停用和卸载保持企业市场流程。分发使用在线席位和发布快照。

### 8.3 页面

插件市场页复用现有社区插件市场（`dshmarket`）的列表、搜索、安装、更新、启用、停用和卸载。页内说明当前允许安装网络插件。加载失败时保留页签，列表区显示失败和重试，不能把读取失败显示成空市场。

`dshmarket` 的目录界面由它自己的客户端注册，宿主不能单独隐藏。关闭插件市场时，桌面端把它移出当前 Profile 组合并保留安装包；入口最迟在重启 Harness 后消失。打开后，若安装包已在本机，则把它加回组合并提示重启；若尚未安装，设置中显示安装入口。安装和更新的许可在每次操作前按服务端最新策略立即判定，不依赖页面是否已经消失。开启不等于把历史被隔离的具体社区插件重新启用，用户仍需自行安装或启用。

文案走现有 locale，中英文同时提供。

## 9. 工作台

### 9.1 设置页

「工作台」页提供一个本机开关，默认关闭。只有本机记录明确为已开启时才开启。

- 关闭：说明开启后可在左侧会话旁进入工作台。不展示可安装列表。
- 开启：说明左侧已出现「工作台」。三方市场打开时说明列表来自公开市场；关闭时说明公开市场不可用，企业上传目录和本机工作台的展示见 [企业工作台目录 PRD](enterprise-workbench-prd.zh.md)。

开关保存在本机，不上传。切换企业账号不改这个本机偏好，但列表内容和安装许可跟随新租户的策略。

### 9.2 打开三方工作台市场

`allow_third_party_workbenches === true` 且用户已开启工作台时，左侧进入的列表使用现有网络工作台市场：

- 数据来自公开工作台市场目录。
- 保留工作台市场、我的收藏、已安装，以及从市场安装、更新、卸载。
- 本地已经装好的工作台仍出现在已安装中，并保留「本地」标识。
- 允许「制作我的工作台」：在本机开发、安装、自测，也可以按规范投稿到公开工作台市场。

### 9.3 关闭公开市场

`allow_third_party_workbenches === false` 且用户已开启工作台时，不使用公开工作台市场。本企业上传的目录、详情和原包核对见 [企业工作台目录 PRD](enterprise-workbench-prd.zh.md)，该目录不能安装。本机工作台仍按下面的规则使用：

- 不请求、不展示公开工作台市场目录，不提供从该目录安装或更新。
- 展示本机已安装的工作台，以及用户在本机新开发并安装的工作台。卡片保留名称、说明、版本、启用状态；本地开发的工作台保留「本地」标识。
- 保留「制作我的工作台」的本地路径：把开发指令交给 Agent，在本机安装，并按本地自测清单验证。安装完成后出现在本地列表中，可以启用和使用。
- 不提供向公开工作台市场投稿，也不提供市场安装、市场更新、收藏后安装、按远程地址安装。
- 可对已安装项启用、停用、卸载。卸载不删除会话、笔记和收藏。
- 「已安装」为空时，说明本机还没有工作台，用户可以在本机开发并安装自己的工作台。不引导用户从公开市场安装。企业目录为空是另一段文案，见企业工作台目录 PRD。
- 读取本机列表失败时显示失败和重试，不回退到公开目录。

已安装的网络工作台在开关关闭后仍可使用、停用、再次启用和卸载，只是不能再从网络更新或新装。此后新开发的本地工作台不受这个限制。

## 10. 安装拦截

隐藏按钮不是策略。所有新增安装入口在执行前读取当前租户能力；读失败则拒绝本次新增安装。

插件在 `allow_third_party_plugins === false` 时拦截：

- 社区插件市场安装和更新。
- 插件管理器对网络来源的安装：包名、Git 地址、远程压缩包。
- 启用 `dshmarket`。它会把插件市场页编回当前 Profile。判断发生在写入 Profile 之前。
- 已安装且当前启用的插件不被这次检查停掉。停用、卸载和已安装插件的本地再次启用保持可用。

明确放行的插件：

- 安装包自带的官方 optional bundle 和宿主保护包的启用、停用。
- 本机绝对路径目录和本机压缩包的新增安装，以及安装后的启用、停用、卸载。来源记在 generation 的 `sourceSpec` 里，重启后仍按本机来源放行。

工作台在 `allow_third_party_workbenches === false` 时拦截网络来源：

- 工作台市场安装和更新。
- `POST /api/desktop-workbenches/market-install`，以及任何按公开 catalog 身份拉取 npm、GitHub Release 或远程源码的安装。
- 远程 URL 和外部下载地址上的工作台包。

网络来源与本机开发的判定依据：安装目标是否携带公开 catalog 的 `distribution` 或落入 `desktop-workbenches/market-installs.json` 的市场安装记录。携带即网络来源，受本开关约束；用户在本机开发、通过本机目录或本机包安装、不经过公开 catalog 的工作台不受约束。判定基于安装请求的实际来源，不依赖界面按钮是否隐藏。

明确放行：

- 「来自企业」的插件安装和更新。
- 用户在本机开发的工作台安装到本机，以及安装后的打开、启用、停用和卸载。本地安装来源是本机目录或本机包，不经过公开工作台市场。
- 两个开关为 `false` 时，对已经安装内容的打开、停用、卸载，以及不访问网络的再次启用。`dshmarket` 在三方插件市场关闭时不能启用。官方自带插件和本机插件可以启用。
- 宿主预置插件和宿主预置工作台运行时，不把它们当成第三方包。

交叉场景：

- 只允许三方插件时，网络插件可以安装，网络工作台安装返回拒绝。工作台页只显示本地数据，本机开发的工作台仍可安装和使用。
- 只允许三方工作台时，网络工作台可以安装，网络插件安装返回拒绝。设置中不出现插件市场页。
- 用户在界面打开后、安装完成前，管理员把对应开关关掉：本次安装失败，已下载但未发布的临时文件按现有安装失败路径清理，不写入已安装记录。

拒绝时给用户可理解的原因，例如「当前企业未开放网络插件安装」或「当前企业未开放网络工作台安装」。日志保留入口和租户标识，不记录 token。

## 11. 实现接缝与时序

本节说明策略从读取到执行跨的进程边界，供设计评审对齐，不定义最终代码形态。

数据流：

- 读取在持有企业凭据的一侧完成。capabilities 复用主进程既有的 `/v1/market` 企业 Broker 通道（`parseMarketRequest` 已允许 `capabilities` endpoint），渲染进程不直接请求 BiSheng 公开地址，也不持有 access token。
- 主进程把解析后的两个布尔值投影进企业状态（与 `/api/enterprise.state` 同一份公开状态），渲染层据此决定是否显示插件市场页、工作台列表数据源和入口。
- 入口显隐只是展示。安装许可由执行安装的后端做最终判定，不信任渲染层传入的布尔或已隐藏的按钮。

执行点：

- 插件拦截沿用现有 `restrictCommunityPackageBackend` 与 `src/main/state/community-plugin-policy.ts`。当前 `communityPluginInstallAllowed()` 固定返回 `false`；本次改为读取当前登录租户的 `allow_third_party_plugins`。未登录或策略不可用时维持关闭。
- 工作台拦截点在 `market-install` 与 catalog 请求所在的工作台后端，按 `allow_third_party_workbenches` 判定网络来源安装；本机开发安装路径不经过该判定。
- 两个执行点都从同一份当前租户策略取值，避免渲染层与后端判定不一致。

启动时序：

- `enforceCommunityPluginPolicy` 等 Profile 启动维护运行在企业登录之前，此时没有 capabilities。启动阶段不再无条件隔离第三方插件与工作台，仅保证已安装内容可加载。
- 策略在企业登录成功、读到 capabilities 之后生效，并且只约束之后的新增网络安装，不回溯隔离或停用启动时已加载的内容。
- 退出登录或切换租户后，按新的登录态重新取值；无有效登录时两个开关按关闭，只影响新增安装，不动已安装内容。

Safe Mode：

- Safe Mode 仍只加载安装包自带的宿主包，第三方插件和工作台在该模式下按既有规则停用。本次新增的插件市场页与工作台网络列表不在 Safe Mode 中提供。
- Safe Mode 的现有文案「从企业插件市场安装」保持不变；它指「来自企业」，不是本次的插件市场页。

## 12. 会话与租户

- 退出登录后立即隐藏插件市场、来自企业和工作台页签，并隐藏左侧工作台入口。本机「已开启工作台」偏好保留，下次登录成功后再决定是否显示。
- 同一时刻只采用当前登录租户的策略。
- capabilities 与企业市场请求继续走现有凭据边界。渲染进程不持有 access token，不直接请求 BiSheng 公开地址。

## 13. 与当前实现的差异

当前企业版把社区插件安装固定为关闭，并在启动时隔离社区插件。本次之后：

- 安装许可改由 capabilities 的两个字段决定，不再使用安装包内的固定关闭。
- 字段为 `false` 时，不再自动隔离、停用或删除已安装的第三方插件和工作台。
- 工作台总开关从隐藏改为设置里的「工作台」页；默认仍是关闭。
- 公开工作台列表按 `allow_third_party_workbenches` 决定是否展示。关闭时展示企业上传目录和本地工作台，企业目录的范围见 [企业工作台目录 PRD](enterprise-workbench-prd.zh.md)。

升级已有用户：

- 服务端未配置时两个字段都为 `false`。已经上线的企业没有打开开关时，升级后仍然不能安装网络插件和网络工作台。
- 管理员在安装设置中明确打开对应开关后，桌面端才显示插件市场或网络工作台市场。
- 本机没有「工作台已开启」记录的用户，升级后左侧仍然没有工作台，直到用户在新页签里打开。打开后，在网络市场关闭时可以安装自己开发的工作台。
- 已经安装的插件、工作台和数据保留。

## 14. 验收

策略：

- 四个开关组合都核对页签、左侧入口、列表数据源和实际安装结果。
- 只关插件时，企业插件、官方自带插件和本机插件仍可安装或启用；网络插件的市场、包名、Git 和远程地址入口都失败。已经装在本机的插件可以停用、卸载和再次启用。`dshmarket` 不能启用。
- 只关工作台时，网络插件仍可安装；工作台市场安装、更新和远程地址安装失败。本机新开发的工作台可以安装、打开和卸载，已安装工作台同样可以打开和卸载。
- 安装过程中开关从开到关，新安装不留下可用版本。

界面：

- 插件市场页签位于「来自企业」右侧。
- 工作台页签位于插件市场右侧；插件市场隐藏时，位于「来自企业」右侧。
- 打开工作台后，左侧「工作台」与「会话」并列；关闭后左侧入口消失，当前会话仍在。
- 中英文、加载中、失败重试、空列表和无权限都有文案。深色主题下页签和开关可见。

契约：

- 请求只带 DSH access token，不带租户选择头。
- `status_code === 200` 且字段缺失、字段不是布尔、`status_code` 非 200、未登录或网络失败时，两个开关都按关闭，不放行网络安装。本机工作台开发安装不受这两个字段缺失的影响。
- 退出、切换租户后不沿用上一份策略。
- 响应里的其他 capabilities 字段缺失时，不导致这两个开关解析失败。

接缝与时序：

- 启动阶段（登录前）不隔离已安装的第三方插件与工作台，已安装内容可加载。
- 渲染层入口被篡改或布尔被伪造时，后端仍按当前租户策略拒绝网络安装。
- 开启插件市场时 `dshmarket` 在活动 Profile 可用，关闭时不新增可见入口。
- 本机开发安装的工作台不被 `allow_third_party_workbenches === false` 拦截；`market-install` 在同一状态下被拒绝。

回归：

- 「来自企业」的安装、更新、启用、停用和卸载保持企业市场流程。分发使用在线席位和发布快照。
- 宿主预置插件仍可按原规则启用和停用。
- 关闭工作台不删除 `desktop-workbenches` 下的会话绑定、笔记、收藏和已安装记录。
