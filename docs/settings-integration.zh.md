# 企业员工的统一设置

## 已确认的范围

面向企业普通员工，简洁易用，沿用桌面现有风格。常用栏目为通用、账号与安全、用量与存储、扩展功能、关于与帮助。模型、Agent、个人密钥与执行参数渐进展开。审批与通知有独立入口。

## 实现边界

- 属于客户端激活/呈现阶段：复用 Harness 设置外框与 feature-owned rows；补充 `settings.navigation`、`settings.general.layout`、`settings.actions.layout`、`settings.plugins.layout` 四个 single/root 布局 slot，保留无贡献项时的默认界面。新宿主插件负责分组及文案，owner 提供行或页的 ID、label 和保留原组件的 render 回调；每项最多挂载一次，无贡献项时保留原出口。不更改全局 slot 注册竞争规则，不移动 React DOM。
- 设置的权威存储保持不变：Harness 的本机设置、主进程企业凭据库、毕昇后端的账号与云端用量分别由现有服务维护。不迁移或清空用户配置。
- 企业网页复用现有隔离文档与 cookie session，通过明确白名单设置页进入内容模式。网页不获得文件、进程或通用 IPC 能力；退出由主进程企业服务执行。
- 远程设置占用设置内容区域，关闭后恢复此前的聊天/模块路由。普通 Profile 启用整合；Safe Mode 只保留能独立使用的本机设置，企业功能不阻断恢复。
- 新插件与其他宿主插件一样从当前 Desktop 安装入口投影，使用现有解析基准；不改变 launch-root、Profile、宿主 fallback 或 bootstrap 顺序。
- 原始网络/导航错误留在对应服务日志，UI 提供重试和返回本机设置。旧网页缺少内容模式就绪报告时不将完整网页覆盖到本机设置上。

覆盖常用/高级分组、未知第三方贡献不丢失、每项只挂载一次、中英文、深浅主题、离线/未登录、受限页面、异步过期、身份切换、退出和返回原页面。干净 npm ci 重放补丁，typecheck、build、完整测试、diff-check；真实 Harness 与临时 Profile 验证实际加载。网页使用各自仓库检查；安装包与 Windows 原生验收单独记录，不能由 macOS 源码测试代替。

上游提供等价导航/行布局扩展点后删除对应补丁并迁移宿主贡献项。

## 兼容接缝

目标版本为 `@deepseek-ai/dsh-client-ui-settings`、`settings-general`、`settings-plugins` 的 `0.2.0-rc.2`。现有 section / item / tab slot 允许增加贡献项，但不能重组导航和常用/高级呈现，因此补充四个布局出口，而不是覆盖已有注册项或复制设置组件。缺少宿主贡献时，各出口继续渲染原来的完整内容。

主进程状态通过 `settingsProtocolVersion: 1` 声明内容模式协议。宿主设置贡献项和唯一几何 presenter 都检查版本；旧桌面主进程没有该能力时，不发送设置区域的可见呈现，而是提示完全退出并重新启动客户端，避免旧主进程忽略 `settings` 字段后显示先前的知识空间或聊天。主进程在呈现和焦点转移时还会核对实际 origin、设置路径与 `dshSettings=1`；文档完整导航或离开设置路由后撤销就绪状态，需要新报告。

主进程接收 `EnterpriseChatPresentation.settings` 的枚举值，仅允许账号、用量、个人接入及三类审批/通知页。嵌入网页通过受限 preload 报告当前设置页就绪，主进程核对 origin、主 frame、实际路径和身份 generation 后才展示内容。关闭与 Tab 焦点交接也只接受当前设置文档；网页不获得主窗口的更新、文件或恢复 API。旧网页缺少就绪报告时，显示兼容错误并保留本机设置与退出路径。

网页只在原生嵌入状态和 `dshSettings=1` 同时成立时使用内容模式，独立网页的导航、语言与登录偏好保持原有行为。审批复用父设置页的计数刷新，避免重复订阅及轮询；通知内进入审批详情时不改变宿主选中的设置页。
